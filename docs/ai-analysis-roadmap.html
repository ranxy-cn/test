① 现状盘点 —— 地板已经打好

以下能力均已上线并经真实故障验证，是 AI 分析的输入与执行底座：

Zabbix 5.0 指标采集（主动模式 agent，CPU/内存/磁盘/负载，分钟级） history / trends API 取数通路（排障中反复验证） 告警策略（阈值宏 + 窗口，主动/被动双模板树覆盖） webhook → 异常事件链路（abnormal / recovered 全闭环） 异常时刻 SSH 快照（进程 / 端口 / 会话，已修复认证） 远程压测演练（CPU / 内存，可编程注入） 通知中心 + 通知渠道 LLM 接入（分析与建议定位，OPENAI 兼容接口）
关键判断：不需要新建数据管道。取数、告警、快照、通知、LLM 五条通路全部现成，AI 分析层是「纯增量」，每一层都能独立上线、独立产生价值。

② 总体架构 —— 统计管「是不是」，LLM 管「为什么」

不让 LLM 直接算指标（慢、贵、不可复现）；统计引擎输出结构化偏差事实，LLM 只消费事实做解释与建议。

采集层（已有）Zabbix history/trends、事件 webhook、SSH 快照
统计引擎（新）时段基线 / 分位数 / 趋势外推 / 聚类，输出结构化「偏差事实」
LLM 分析器（新）消费偏差事实 + 快照 + 主机档案 → 根因假设 / 影响面 / 建议
呈现层（已有+新）异常详情页 AI 面板、事故视图、通知中心周报
证据链（已有理念）每条分析附：输入数据 id、模型、提示词版本、时间戳

方向 A · 历史基线偏差检测 建议第一步

你提出的「按周对比 CPU」的工程化版本。解决触发器抓不到的异常：没超阈值，但显著偏离自己的历史。

做法

  • 基线建模：定时任务按「星期 × 小时」分桶，取近 4 周同时段样本，算 P5 / P50 / P95 分位（比均值±3σ 更抗离群值）。维度：CPU、内存、磁盘、负载、网络流量。
  • 偏差判定：当前值 > P95 且持续 ≥ N 个采样点 → 产生结构化偏差事件（超 P95 幅度倍数、持续时长、基线值三要素）。
  • 时段感知：工作日 / 周末分开建模，避免「周日来批处理」被误判；冷启动期（样本 < 2 周）只记录不告警。
  • 接入现有链路：偏差事件直接写异常中心，走既有 abnormal → recovered 生命周期，前端零改造即可看到。

方向 B · 告警 AI 解释与聚类降噪

异常触发时自动「带 brain 上门」：把快照、指标、档案喂给 LLM，输出人话版根因分析与建议；多机同爆时聚合成一条事故。

B1 · 告警 AI 摘要（异常详情页新增面板）

  • 触发时机：异常事件落库后异步生成（不阻塞告警链路），生成失败不影响原告警展示
  • 输入：异常时刻 SSH 快照（已有）+ 近 1 小时指标时序 + 该机档案（角色/应用/历史告警）+ 偏差事实（来自 A）
  • 输出四段式：发生了什么 / 影响面 / 建议动作（只建议，不自动执行）/ 置信度
  • 证据链：面板标注输入数据 id + 模型 + 提示词版本，一键展开原始输入

B2 · 多机告警聚类（事故视图）

  • 滑动时间窗（如 5 分钟）内同母机下 ≥ K 台子机同类告警 → 合并为一条「事故」，保留子告警明细
  • 统计归因线索：同宿主机（共享内核，你们已实际踩过影子告警）、同网段、同应用分组、同配置版本
  • 事故条目优先展示归因假设，点开看成员机器与各自曲线

方向 C · 容量预测与健康周报

从「被动等告警」到「提前打招呼」。

C1 · 磁盘 / 内存增长预测

  • 对磁盘使用率做趋势外推（Holt-Winters / 稳健线性回归，剔除夜间静默期）
  • 预测触达 85% / 95% 的日期，提前生成「预计 N 天后满」预警，随偏差事件一起进异常中心
  • 每天重算一次，数据量小（每机每天 288 点 × 保留天数），单机毫秒级

方向 D · 压测演练 AI 解读（闭环彩蛋）

压测的最后一公里：从「打上去看曲线」到「自动出结论」。

  • 压测结束自动对比：压测前 10 分钟 vs 压测中 vs 恢复后 10 分钟的 CPU / 负载 / 采集延迟
  • 校验告警链路：本次压测是否如预期触发 → 未触发时给出原因假设（时长不足 / 窗口均值稀释）——你们已经真实踩过「4 分钟压测喂不饱 5 分钟窗口」的坑
  • 输出压测报告：到达的峰值、恢复耗时、告警触发延迟，LLM 总结瓶颈判断

③ 实施路线 —— 三阶段，每段独立可上线

阶段一 · 地基：统计引擎上线
内容：A 基线建模 + 偏差事件接入异常中心；数据表（baselines / deviation_events）；冷启动只记录不告警。
验收：跑满一周后，人工注入异常（复用压测），异常中心出现「偏离基线」事件且正常时段零误报。
阶段二 · 智能：LLM 解释与降噪
内容：B1 告警 AI 摘要面板（异步生成 + 证据链标注）；B2 事故聚类视图；D 压测解读顺带完成。
验收：每次告警 30 秒内可读到大体靠谱的中文根因摘要；影子告警场景能聚成一条事故并给出宿主归因。
阶段三 · 前瞻：预测与周报
内容：C1 容量预测卡；C2 每周健康周报推送。
验收：预测日期与实际触达日期误差 ≤ 2 天；周报准时送达且数字与源数据可对账。
依赖关系：阶段一是阶段二/三的地基（偏差事实是 LLM 的输入、也是周报素材）；B1 可与 A 并行开发（先用触发器告警当输入，A 上线后自动升级为偏差事件输入）。

④ 风险与对策

风险对策
LLM 幻觉 / 误导性建议所有建议标注「仅建议，不自动执行」；面板强制展示证据链（输入数据 id + 提示词版本）；置信度低时明说「证据不足」，不硬编故事。
基线误报（变更后历史失效）分位数窗口天然抗噪；检测到「连续多天全面偏离」时自动进入重新收敛期（重建基线而非持续报警）；冷启动静默。
LLM 成本失控LLM 仅在「告警触发 / 周报 / 手动点击」三个时机调用，日常指标分析全部走本地统计；单次输入控制在 2K token 内（快照已截尾）。
告警风暴 / 事件淹没B2 聚类前置：同宿主、同分组的同源告警合并；异常中心默认折叠已恢复事件。
小样本时段（周末 / 新机）样本不足自动降级为「仅周粒度基线」或静默积累，绝不硬造基线。
